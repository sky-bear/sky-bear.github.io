# HTTP与网络通信详解

## HTTP请求流程

### 浏览器中输入URL到页面加载完成的过程

1. **URL解析**：浏览器解析输入的URL，识别协议(http/https)、域名和路径
2. **DNS解析**：将域名转换为IP地址
   - 检查浏览器缓存
   - 检查操作系统缓存
   - 检查路由器缓存
   - 向ISP的DNS服务器查询
   - 递归查询根域名服务器
3. **建立TCP连接**：与服务器进行TCP三次握手
   - 客户端发送SYN包
   - 服务器返回SYN+ACK包
   - 客户端发送ACK包确认
4. **TLS握手**（如果是HTTPS）：
   - 客户端和服务器协商加密算法
   - 服务器发送证书
   - 客户端验证证书
   - 生成对称加密密钥
5. **发送HTTP请求**：
   - 包括请求行（方法、路径、协议版本）
   - 请求头（Host、User-Agent、Accept等）
   - 请求体（POST等方法的数据）
6. **服务器处理请求**：
   - 接收请求并路由到相应处理程序
   - 生成响应内容
7. **返回HTTP响应**：
   - 状态行（协议版本、状态码、状态描述）
   - 响应头（Content-Type、Content-Length等）
   - 响应体（HTML、JSON等数据）
8. **浏览器解析渲染页面**：
   - 解析HTML构建DOM树
   - 解析CSS构建CSSOM树
   - 合并为渲染树
   - 布局和绘制页面
9. **关闭TCP连接**（除非启用Keep-Alive）

## HTTP基础知识

### HTTP请求方法

- **GET**：获取资源，参数附加在URL中，不改变服务器状态，有长度限制
- **POST**：提交数据，参数在请求体中，可能改变服务器状态，无长度限制
- **PUT**：上传/更新资源，幂等（多次操作结果相同）
- **DELETE**：删除资源
- **HEAD**：与GET类似，但只返回头信息不返回响应体
- **OPTIONS**：获取目标资源支持的通信选项
- **PATCH**：对资源进行部分修改
- **TRACE**：回显服务器收到的请求，用于测试和诊断
- **CONNECT**：建立隧道连接

### POST和GET的主要区别

| 特性 | GET | POST |
|------|-----|------|
| 数据位置 | URL参数 | 请求体 |
| 可见性 | 参数在URL中可见 | 参数在请求体中不可见 |
| 长度限制 | 受URL长度限制(通常<2KB) | 无严格限制 |
| 缓存 | 可缓存 | 通常不缓存 |
| 书签 | 可添加书签 | 不可添加书签 |
| 历史记录 | 参数保留在浏览历史中 | 参数不会保留 |
| 数据类型 | 只允许ASCII字符 | 无类型限制 |
| 幂等性 | 幂等（多次请求结果相同） | 非幂等 |
| 安全性 | 较低，数据暴露在URL中 | 相对较高 |
| 适用场景 | 数据获取、简单查询 | 表单提交、大量数据传输 |

### HTTP持久连接(Keep-Alive)

**定义**：允许在单个TCP连接上发送多个HTTP请求/响应，而不必为每个请求/响应对创建新连接。

**工作原理**：
1. 客户端在请求头中添加`Connection: keep-alive`
2. 服务器在响应中也返回`Connection: keep-alive`
3. 连接保持打开状态，可用于后续请求
4. 可通过`Keep-Alive: timeout=5, max=100`等方式设置超时和最大请求数

**优势**：
- 减少TCP握手/挥手次数，降低延迟
- 允许TCP慢启动机制有效工作
- 降低CPU和内存使用

### HTTP状态码

- **200 OK**：请求成功，服务器已返回请求的数据
- **301 Moved Permanently**：永久重定向，请求的资源已被永久移动到新位置
- **404 Not Found**：服务器找不到请求的资源
- **500 Internal Server Error**：服务器内部错误，无法完成请求

其他常见状态码：
- 1xx：信息响应
- 2xx：成功响应
  - 201 Created：已创建资源
  - 204 No Content：成功但无内容返回
- 3xx：重定向
  - 302 Found：临时重定向
  - 304 Not Modified：资源未修改，使用缓存
- 4xx：客户端错误
  - 400 Bad Request：请求语法错误
  - 401 Unauthorized：需要身份验证
  - 403 Forbidden：服务器拒绝请求
  - 405 Method Not Allowed：不允许的请求方法
- 5xx：服务器错误
  - 502 Bad Gateway：网关错误
  - 503 Service Unavailable：服务不可用
  - 504 Gateway Timeout：网关超时

## HTTPS安全通信

### HTTP vs HTTPS

| 特性 | HTTP | HTTPS |
|------|------|-------|
| 协议 | 明文传输 | 加密传输（HTTP + SSL/TLS） |
| 端口 | 80 | 443 |
| 安全性 | 低，易被窃听、篡改 | 高，加密传输 |
| 证书 | 不需要 | 需要SSL证书 |
| 性能 | 较快 | 略慢（加密解密开销） |
| URL格式 | http:// | https:// |
| 信任标识 | 无 | 浏览器显示锁标志 |
| SEO | 较低排名 | Google优先收录 |

### HTTPS安全性保障

HTTPS通过以下机制保证传输安全：

1. **加密**：使用加密算法确保数据在传输过程中无法被读取
   - 对称加密：使用相同密钥加密解密（AES、DES）
   - 非对称加密：使用公钥加密，私钥解密（RSA、ECC）
   - 混合加密：协商对称密钥过程使用非对称加密，数据传输使用对称加密

2. **数据完整性**：确保数据在传输过程中不被篡改
   - 使用消息认证码（MAC）或数字签名

3. **身份验证**：验证通信方的身份
   - 使用数字证书验证服务器身份

### SSL/TLS协议

**定义**：安全套接层(SSL)/传输层安全(TLS)协议，位于HTTP与TCP之间，负责加密通信数据。

**TLS握手过程**：
1. 客户端发送ClientHello，包含支持的加密套件和随机数
2. 服务器回应ServerHello，选择加密套件和自己的随机数
3. 服务器发送证书和ServerHelloDone消息
4. 客户端验证证书，生成预主密钥(Pre-Master Secret)
5. 客户端使用服务器公钥加密预主密钥并发送
6. 双方使用随机数和预主密钥生成会话密钥
7. 客户端发送ChangeCipherSpec和Finished消息
8. 服务器发送ChangeCipherSpec和Finished消息
9. 握手完成，使用会话密钥加密后续通信

**TLS版本演进**：
- SSL 2.0/3.0：已弃用，存在安全漏洞
- TLS 1.0/1.1：已被现代浏览器废弃
- TLS 1.2：目前应用广泛
- TLS 1.3：最新版本，简化握手过程，提高性能和安全性

### 证书颁发机构(CA)

**作用**：
1. 验证服务器身份并颁发数字证书
2. 作为可信第三方，建立信任链
3. 维护证书吊销列表(CRL)

**工作流程**：
1. 网站创建证书签名请求(CSR)并提交给CA
2. CA验证申请者身份
3. CA使用自己的私钥签名证书并颁发给网站
4. 网站部署该证书
5. 客户端接收证书，使用CA的公钥验证证书有效性

**证书层级**：
- 根证书：自签名，内置于操作系统和浏览器中
- 中间证书：由根CA签名
- 叶子证书：由中间CA签名，颁发给网站

## HTTP协议演进

### HTTP/1.1与HTTP/2对比

| 特性 | HTTP/1.1 | HTTP/2 |
|------|----------|--------|
| 连接数 | 每个域名有限制 | 单一TCP连接 |
| 数据格式 | 文本格式 | 二进制格式 |
| 头部压缩 | 无压缩 | HPACK头部压缩 |
| 多路复用 | 不支持 | 支持并行请求和响应 |
| 服务器推送 | 不支持 | 服务器可主动推送资源 |
| 请求优先级 | 不支持 | 支持设置流优先级 |
| 流控制 | 无 | 有流控制机制 |
| 安全性 | 可选TLS | 实践中要求TLS |

**HTTP/2主要改进**：
1. **二进制分帧**：将消息分解为更小的帧，以二进制方式传输
2. **多路复用**：在同一连接上同时处理多个请求/响应
3. **头部压缩**：减少重复传输的头信息
4. **服务器推送**：服务器可预测客户端需要的资源并主动推送
5. **请求优先级**：为不同请求设置优先级

### HTTP缓存控制

**通过HTTP头控制缓存**：
1. **强缓存**：不向服务器发请求，直接使用缓存
   - `Cache-Control: max-age=31536000`（秒）
   - `Expires: Wed, 21 Oct 2025 07:28:00 GMT`（绝对时间，已弃用）

2. **协商缓存**：向服务器确认资源是否有变更
   - `If-Modified-Since` / `Last-Modified`（基于修改时间）
   - `If-None-Match` / `ETag`（基于内容摘要，更精确）

3. **Cache-Control指令**：
   - `no-cache`：强制向服务端验证（使用协商缓存）
   - `no-store`：不使用任何缓存
   - `private`：只允许浏览器缓存
   - `public`：允许中间缓存服务器缓存
   - `must-revalidate`：过期后必须验证
   - `max-age`：最大缓存时间（秒）
   - `s-maxage`：针对代理服务器的最大缓存时间

### HTTP/3特点与改进

**HTTP/3主要特点**：
1. **基于QUIC协议**：替代TCP+TLS，使用UDP
2. **减少连接建立延迟**：0-RTT或1-RTT连接建立
3. **改进的多路复用**：避免TCP的队头阻塞问题
4. **连接迁移**：支持网络切换（如WiFi切换到4G）而不中断连接
5. **前向纠错**：某些情况下避免重传

**与HTTP/2的区别**：
1. **传输层协议**：HTTP/2基于TCP，HTTP/3基于UDP+QUIC
2. **握手延迟**：HTTP/3通常需要更少的RTT建立连接
3. **丢包处理**：HTTP/3在单个流丢包不影响其他流
4. **加密集成**：HTTP/3将安全功能直接集成到协议中
5. **适应性**：HTTP/3更适合移动和不稳定网络环境

## 内容分发网络(CDN)

### CDN基本工作原理

1. **内容分发**：将网站内容分发到全球各地的服务器节点
2. **就近访问**：用户从最近的节点获取内容，减少延迟
3. **流量分配**：通过DNS解析将用户导向最优节点
4. **缓存策略**：缓存静态资源，减轻源服务器负担
5. **智能路由**：根据节点负载、网络状况动态调整路由

### CDN优势与缺点

**优势**：
- 减少延迟，提高加载速度
- 分散流量，减轻源服务器负担
- 提高可用性和冗余性
- 防御DDoS攻击
- 节约带宽成本
- 全球覆盖，提升国际用户体验

**缺点**：
- 额外成本
- 增加配置复杂度
- 缓存更新延迟
- 对动态内容支持有限
- 可能因节点故障影响服务
- 依赖第三方服务可能带来安全风险

### 前端项目中CDN使用

**最佳实践**：
1. **选择合适的CDN提供商**：
   - 根据用户地理分布选择覆盖范围
   - 考虑性能、可靠性、价格和支持

2. **资源优化**：
   - 对静态资源（JS、CSS、图片）使用CDN
   - 使用文件名哈希或版本号进行缓存控制
   - 配置适当的缓存策略

3. **实现**：
   ```html
   <!-- 使用公共CDN加载库 -->
   <script src="https://cdn.jsdelivr.net/npm/vue@2.6.14/dist/vue.min.js"></script>

   <!-- 自有资源CDN -->
   <link href="https://your-cdn.com/styles/main.a8f3d2e1.css" rel="stylesheet">
   ```

4. **回退策略**：
   ```javascript
   <script>
     window.onError = function(error) {
       // CDN加载失败时从备用源加载
       const script = document.createElement('script');
       script.src = '/local/fallback/vue.min.js';
       document.head.appendChild(script);
     }
   </script>
   <script src="https://cdn.jsdelivr.net/npm/vue@2.6.14/dist/vue.min.js" 
           onerror="window.onError(this)"></script>
   ```

### CDN节点宕机应对策略

1. **多CDN策略**：使用多个CDN提供商
2. **回源机制**：CDN不可用时直接访问源站
3. **健康检测**：定期检测CDN状态
4. **本地缓存**：利用浏览器缓存降低CDN依赖
5. **降级方案**：提供简化版界面
6. **实时监控**：使用监控工具及时发现问题

## DNS系统

### DNS服务器作用

**DNS**(Domain Name System)负责将域名转换为IP地址，主要功能：
- 域名解析：将域名翻译成IP地址
- 负载均衡：通过轮询或地理位置返回不同IP
- 缓存：减少重复查询
- 分层管理：根域、顶级域、二级域等层次化管理

**DNS服务器类型**：
- 根域名服务器
- 顶级域名服务器(.com, .org等)
- 权威DNS服务器(特定域的权威解析)
- 本地DNS服务器(ISP提供的递归解析器)

### DNS解析过程

1. **检查浏览器缓存**
2. **查询操作系统缓存**：检查hosts文件和本地DNS缓存
3. **递归查询**：
   - 向本地DNS服务器查询
   - 如果本地DNS无缓存，从根域名服务器开始查询
   - 根域名服务器返回顶级域名服务器地址
   - 顶级域名服务器返回权威域名服务器地址
   - 权威域名服务器返回最终IP地址
4. **缓存结果**：各级缓存查询结果
5. **返回IP地址**：浏览器获得IP地址并建立连接

### DNS预解析优化

**DNS预解析**：提前解析可能需要访问的域名，减少用户实际请求时的等待时间

**实现方法**：
```html
<!-- 使用link标签预解析 -->
<link rel="dns-prefetch" href="//fonts.googleapis.com">
<link rel="dns-prefetch" href="//cdn.example.com">

<!-- 对于跨域资源，先打开预连接 -->
<meta http-equiv="x-dns-prefetch-control" content="on">
```

**前端优化应用**：
1. 预解析第三方资源域名
2. 预解析可能的API域名
3. 预解析可能的重定向目标域名
4. 根据用户行为预测并预解析可能访问的域名

## TCP与UDP

### TCP与UDP基本区别

| 特性 | TCP | UDP |
|------|-----|-----|
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 可靠传输，保证顺序 | 不可靠传输 |
| 传输方式 | 字节流 | 数据报 |
| 速度 | 较慢 | 较快 |
| 头部大小 | 20-60字节 | 8字节 |
| 流量控制 | 有（滑动窗口） | 无 |
| 拥塞控制 | 有 | 无 |
| 应用场景 | 网页、邮件、文件传输 | 视频流、游戏、VoIP |

### TCP三次握手

1. **第一次握手**：客户端发送SYN包(seq=x)到服务器，进入SYN_SENT状态
2. **第二次握手**：服务器收到SYN包，回应SYN+ACK包(seq=y, ack=x+1)，进入SYN_RECEIVED状态
3. **第三次握手**：客户端收到SYN+ACK包，回应ACK包(ack=y+1)，进入ESTABLISHED状态；服务器收到ACK后也进入ESTABLISHED状态

**为什么需要三次握手**：
- 确认双方的发送和接收能力都正常
- 避免历史连接干扰
- 同步双方初始序列号

### TCP四次挥手

1. **第一次挥手**：客户端发送FIN包(seq=u)，进入FIN_WAIT_1状态
2. **第二次挥手**：服务器收到FIN包，发送ACK包(ack=u+1)，进入CLOSE_WAIT状态；客户端收到ACK后进入FIN_WAIT_2状态
3. **第三次挥手**：服务器发送FIN包(seq=v)，进入LAST_ACK状态
4. **第四次挥手**：客户端收到FIN包，发送ACK包(ack=v+1)，进入TIME_WAIT状态；服务器收到ACK后关闭连接，客户端等待2MSL后关闭连接

**为什么需要四次挥手**：
- 关闭连接是全双工的，每个方向都需要单独关闭
- 服务器收到客户端的FIN后可能还有数据需要发送
- TIME_WAIT确保最后一个ACK能到达对方

### TCP可靠性保证机制

1. **序列号与确认应答**：每个包都有序列号，接收方发送确认号
2. **超时重传**：发送方未收到确认就重发数据
3. **校验和**：检测数据是否损坏
4. **流量控制**：使用滑动窗口机制匹配收发速率
5. **拥塞控制**：避免网络过载
   - 慢启动
   - 拥塞避免
   - 快速重传
   - 快速恢复

### TCP拥塞控制

**拥塞控制算法**：
1. **慢启动**：
   - 初始cwnd=1，每收到一个ACK，cwnd+=1
   - 指数增长，直到达到阈值ssthresh

2. **拥塞避免**：
   - 当cwnd>=ssthresh时，每个RTT，cwnd+=1
   - 线性增长

3. **拥塞检测**：
   - 超时：表明网络严重拥塞
     - ssthresh = cwnd/2
     - cwnd = 1
     - 返回慢启动阶段
   - 收到3个重复ACK：轻微拥塞
     - ssthresh = cwnd/2
     - cwnd = ssthresh + 3
     - 快速恢复

4. **快速恢复**：
   - 每收到重复ACK，cwnd+=1
   - 收到新数据ACK，cwnd=ssthresh
   - 返回拥塞避免阶段

### UDP适用场景

**UDP适合实时应用的原因**：
- 低延迟：无需连接建立和拥塞控制
- 无阻塞：丢包不影响后续数据传输
- 开销小：头部简单，处理快
- 适合周期性数据：可接受部分丢失

**适用UDP的情况**：
- 实时性要求高，可接受少量丢包
- 网络良好，丢包率低
- 数据包小且独立
- 单向通信，不需要大量反馈
- 应用有自己的可靠性机制

**例如**：DNS查询、视频会议、在线游戏、流媒体传输、物联网数据采集

### TCP粘包问题处理

**粘包原因**：
1. TCP面向字节流，无消息边界
2. Nagle算法合并小包
3. 接收方读取不及时

**解决方案**：
1. **固定长度**：每个消息固定大小，不足部分填充
2. **分隔符**：使用特殊字符标记消息边界
3. **长度前缀**：在数据前加上长度字段
4. **消息格式**：使用TLV(Type-Length-Value)等结构化格式
5. **应用层协议**：使用HTTP、WebSocket等有边界的协议

**代码示例**（长度前缀法）：
```javascript
// 发送端

  header.writeUInt32BE(data.length, 0);
```

## WebSocket技术

### WebSocket协议特点

1. **全双工通信**：服务器和客户端可以同时发送和接收数据
2. **基于TCP**：建立在单个TCP连接上
3. **低延迟**：头部开销小
4. **保持连接**：连接持久化，不需要频繁建立
5. **跨域支持**：不受同源策略限制
6. **子协议支持**：可使用STOMP等子协议

**与HTTP的关系**：
- 使用HTTP进行握手升级
- 使用80/443端口，便于穿越防火墙
- 建立连接后，协议独立于HTTP

### WebSocket心跳与重连

**心跳机制**：
```javascript
class HeartbeatWebSocket {
  constructor(url) {
    this.url = url;
    this.socket = null;
    this.heartbeatTimer = null;
    this.reconnectTimer = null;
    this.reconnectAttempts = 0;
    this.maxReconnectAttempts = 5;
    this.reconnectInterval = 3000;
    this.heartbeatInterval = 30000;

    this.connect();
  }

  connect() {
    this.socket = new WebSocket(this.url);

    this.socket.onopen = () => {
      console.log('连接已建立');
      this.reconnectAttempts = 0;
      this.startHeartbeat();
    };

    this.socket.onmessage = (event) => {
      // 处理消息，如果是心跳响应，重置心跳定时器
      if (event.data === 'pong') {
        this.resetHeartbeat();
      } else {
        // 处理业务消息
        console.log('收到消息:', event.data);
      }
    };

    this.socket.onclose = (event) => {
      console.log('连接已关闭');
      this.stopHeartbeat();
      this.reconnect();
    };

    this.socket.onerror = (error) => {
      console.error('WebSocket错误:', error);
      this.socket.close();
    };
  }

  startHeartbeat() {
    this.heartbeatTimer = setInterval(() => {
      if (this.socket.readyState === WebSocket.OPEN) {
        this.socket.send('ping');

        // 设置超时检测
        this.heartbeatTimeout = setTimeout(() => {
          console.log('心跳超时，关闭连接');
          this.socket.close();
        }, 5000);
      }
    }, this.heartbeatInterval);
  }

  resetHeartbeat() {
    if (this.heartbeatTimeout) {
      clearTimeout(this.heartbeatTimeout);
    }
  }

  stopHeartbeat() {
    if (this.heartbeatTimer) {
      clearInterval(this.heartbeatTimer);
    }
    if (this.heartbeatTimeout) {
      clearTimeout(this.heartbeatTimeout);
    }
  }

  reconnect() {
    if (this.reconnectAttempts < this.maxReconnectAttempts) {
      this.reconnectTimer = setTimeout(() => {
        console.log(`尝试重连 (${this.reconnectAttempts + 1}/${this.maxReconnectAttempts})`);
        this.reconnectAttempts++;
        this.connect();
      }, this.reconnectInterval);
    } else {
      console.log('达到最大重连次数');
    }
  }

  send(data) {
    if (this.socket && this.socket.readyState === WebSocket.OPEN) {
      this.socket.send(data);
    } else {
      console.error('连接未建立，无法发送消息');
    }
  }

  close() {
    this.stopHeartbeat();
    if (this.reconnectTimer) {
      clearTimeout(this.reconnectTimer);
    }
    if (this.socket) {
      this.socket.close();
    }
  }
}

// 使用
const ws = new HeartbeatWebSocket('ws://example.com/socket');
```

### WebSocket与轮询对比

| 特性 | 轮询(Polling) | 长轮询(Long-Polling) | WebSocket |
|------|--------------|---------------------|-----------|
| 连接方式 | 短连接，定时请求 | 长连接，服务器阻塞等待 | 持久全双工连接 |
| 实时性 | 低，受轮询间隔限制 | 中，有一定延迟 | 高，接近实时 |
| 服务器负载 | 高，大量无效请求 | 中，连接保持开销 | 低，按需通信 |
| 带宽消耗 | 高，HTTP头部开销大 | 中 | 低，握手后头部小 |
| 复杂度 | 低，易实现 | 中 | 中到高 |
| 浏览器支持 | 全支持 | 全支持 | IE10+及现代浏览器 |
| 防火墙友好 | 高 | 高 | 中（可能被拦截） |
| 适用场景 | 低频更新、简单应用 | 中等实时性要求 | 高实时性、频繁通信 |

```javascript
class ChatApp {
  constructor() {
    this.username = prompt("请输入您的用户名:") || "游客" + Math.floor(Math.random() * 1000);
    this.chatContainer = document.getElementById("chatContainer");
    this.messageInput = document.getElementById("messageInput");
    this.sendButton = document.getElementById("sendButton");
    this.connectionStatus = document.getElementById("connectionStatus");

    this.connectWebSocket();
    this.bindEvents();
  }

  connectWebSocket() {
    // 在实际应用中替换为你的WebSocket服务器地址
    this.socket = new WebSocket('ws://localhost:8080/chat');

    this.socket.onopen = () => {
      this.connectionStatus.textContent = "已连接";
      // 发送加入消息
      this.socket.send(JSON.stringify({
        type: 'join',
        username: this.username
      }));
    };

    this.socket.onmessage = (event) => {
      const data = JSON.parse(event.data);
      this.handleMessage(data);
    };

    this.socket.onclose = () => {
      this.connectionStatus.textContent = "连接已断开，尝试重新连接...";
      // 尝试重新连接
      setTimeout(() => this.connectWebSocket(), 3000);
    };

    this.socket.onerror = (error) => {
      console.error('WebSocket错误:', error);
      this.connectionStatus.textContent = "连接错误";
    };
  }

  bindEvents() {
    this.sendButton.addEventListener('click', () => this.sendMessage());

    this.messageInput.addEventListener('keypress', (e) => {
      if (e.key === 'Enter') {
        this.sendMessage();
      }
    });

    // 在页面关闭前通知服务器
    window.addEventListener('beforeunload', () => {
      if (this.socket.readyState === WebSocket.OPEN) {
        this.socket.send(JSON.stringify({
          type: 'leave',
          username: this.username
        }));
      }
    });
  }

  sendMessage() {
    const message = this.messageInput.value.trim();
    if (message && this.socket.readyState === WebSocket.OPEN) {
      this.socket.send(JSON.stringify({
        type: 'message',
        username: this.username,
        content: message
      }));
      this.messageInput.value = '';
    }
  }

  handleMessage(data) {
    const messageElement = document.createElement('div');

    switch (data.type) {
      case 'message':
        messageElement.className = `message ${data.username === this.username ? 'self' : 'other'}`;
        messageElement.innerHTML = `<strong>${data.username}</strong>: ${this.escapeHTML(data.content)}`;
        break;

      case 'join':
      case 'leave':
        messageElement.className = 'status';
        messageElement.textContent = `${data.username} ${data.type === 'join' ? '加入了聊天' : '离开了聊天'}`;
        break;
    }

    this.chatContainer.appendChild(messageElement);
    this.chatContainer.scrollTop = this.chatContainer.scrollHeight;
  }

  escapeHTML(text) {
    const div = document.createElement('div');
    div.textContent = text;
    return div.innerHTML;
  }
}

// 初始化应用
document.addEventListener('DOMContentLoaded', () => {
  new ChatApp();
});
```

**服务器端实现**（Node.js + ws库）：

```javascript
const WebSocket = require('ws');
const http = require('http');
const server = http.createServer();
const wss = new WebSocket.Server({ server });

// 存储所有连接的客户端
const clients = new Map();

wss.on('connection', (ws) => {
  const clientId = generateUniqueId();
  let username = '';

  ws.on('message', (message) => {
    try {
      const data = JSON.parse(message);

      switch (data.type) {
        case 'join':
          username = data.username;
          clients.set(clientId, { ws, username });
          broadcastMessage({
            type: 'join',
            username
          });
          console.log(`${username} 加入了聊天`);
          break;

        case 'message':
          if (data.content) {
            broadcastMessage({
              type: 'message',
              username: data.username,
              content: data.content
            });
            console.log(`${data.username}: ${data.content}`);
          }
          break;

        case 'leave':
          removeClient(clientId);
          break;
      }
    } catch (error) {
      console.error('处理消息出错:', error);
    }
  });

  ws.on('close', () => {
    removeClient(clientId);
  });

  ws.on('error', (error) => {
    console.error(`客户端连接错误: ${error.message}`);
    removeClient(clientId);
  });

  // 设置心跳检测
  const pingInterval = setInterval(() => {
    if (ws.readyState === WebSocket.OPEN) {
      ws.ping();
    }
  }, 30000);

  ws.on('pong', () => {
    // 收到pong响应，客户端仍然活跃
    console.log(`${username || clientId} 活跃中`);
  });

  // 清理资源
  ws.on('close', () => {
    clearInterval(pingInterval);
  });
});

function broadcastMessage(data) {
  const message = JSON.stringify(data);
  clients.forEach(({ ws }) => {
    if (ws.readyState === WebSocket.OPEN) {
      ws.send(message);
    }
  });
}

function removeClient(clientId) {
  if (clients.has(clientId)) {
    const { username } = clients.get(clientId);
    clients.delete(clientId);

    if (username) {
      broadcastMessage({
        type: 'leave',
        username
      });
      console.log(`${username} 离开了聊天`);
    }
  }
}

function generateUniqueId() {
  return Math.random().toString(36).substr(2, 9);
}

// 启动服务器
const PORT = process.env.PORT || 8080;
server.listen(PORT, () => {
  console.log(`WebSocket 服务器运行在端口 ${PORT}`);
});
```
