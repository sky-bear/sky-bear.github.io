## ⼩程序和 Web 开发的区别

⽹⻚开发中渲染线程和 JavaScript 线程是互斥的。即这两个线程不能够穿插执⾏，必须串⾏。当其中⼀个线程执⾏时，另⼀个线程只能挂起等待。这也是 JavaScript 线程占⽤主线程时间过⻓，可能会导致⻚⾯失去响应的原因。
⽽在⼩程序中，⼆者是分开的，分别运⾏在不同的线程中，即渲染线程和逻辑线程。

### 通信方式

⼩程序的渲染层和逻辑层之间的通信并不是直接传递数据或事件，⽽是由 Native(微信客⼾端)作为中间媒介进⾏转发。逻辑层发送⽹络请求也是经由 Native 转发

- 渲染层通过与⽤⼾的交互触发特定的事件 event；
- 然后 event 被传递给逻辑层；
- 逻辑层通过⼀系列的逻辑处理、数据请求等操作，叫处理好的 data 传递给渲染层；
- 最后渲染层将 data 渲染为可视化的 UI。
  ⽽渲染层和逻辑层通信的这个过程就是典型的事件驱动模式。
  了解⼩程序的通信⽅式后，想必对关于 setData 的⼀些优化建议也知其所以然了。例如：

- 尽量减少 setData 的调⽤次数和携带的数据⼤⼩
- 尽量减少 JavaScript 代码的复杂度

在逻辑层发⽣数据变更时，通过setData⽅法把数据从逻辑层传递到渲染层，经过前后对⽐，将差异内容应⽤到原有的DOM树上，渲染出更新后的UI界⾯


## ⼩程序的运⾏机制
1. 下载：⽤⼾在微信客⼾端上搜索并点击进⼊⼩程序，微信会从服务器上下载⼩程序的代码包。
2. 启动：当⽤⼾点击进⼊⼩程序时，微信会启动⼩程序的运⾏环境，并加载⼩程序的代码。
3. 渲染：⼩程序的界⾯由两个部分组成，即视图层和逻辑层。视图层由WXML（类似HTML）和WXSS
（类似CSS）组成，逻辑层由JavaScript代码组成。微信客⼾端将WXML和WXSS解析成真实的UI界
⾯，并且执⾏JavaScript代码进⾏数据处理和逻辑控制。
4. 交互：⽤⼾可以与⼩程序进⾏交互操作，⽐如点击按钮、滑动⻚⾯等。微信客⼾端会捕捉⽤⼾的交
互事件，并将事件发送给⼩程序的逻辑层进⾏处理。
5. 数据通信：⼩程序可以通过⽹络请求获取远程数据或与服务器进⾏通信。微信客⼾端会将⽹络请求
发送给微信服务器，然后将响应结果返回给⼩程序的逻辑层。



## 框架
### taro
Taro 1/2 属于编译型架构，主要通过对类 React 代码进行语法编译转换地方式，得到各个端可以运行的代码，再配合非常轻量的运行时适配，以及根据标准组件库、API 进行差异抹平，从而实现多端适配的目的

Taro 3 开始，Taro 走向了一个全新的架构：基于运行时模拟 DOM/BOM 的方式实现多端统一。这个架构可以被称为“解释型”，因为它不再依赖于编译时对 JSX 或模板语法的完全转换，而是尝试让前端框架（如 React、Vue）直接运行在小程序环境中


Taro 3 的设计目标是让小程序拥有接近浏览器的能力，从而打破小程序与 Web 的边界，使开发者可以用熟悉的前端框架进行开发
